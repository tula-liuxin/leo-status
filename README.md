# leo-status

DSH 的 Leo 待办看板与阿源助手。当前开发版本 **0.8.0**，针对 DSH **0.2.1-rc.3**。

## 使用流程

1. 打开「待办 → 数据源」，接入笔记目录或使用自动发现。可选择复选框、标签、frontmatter 和 TODO 标记规则。
2. Obsidian 库（目录含 .obsidian）的待办自动进入看板。其他笔记和会话候选进入阿源的「待确认建议」，Accept 后成为正式待办。
3. 看板待办可完成、取消完成、作废、恢复和删除。本机 Obsidian 待办的操作写回相应笔记行；已接受的建议由插件存储管理。扫描本身不写笔记。
4. 点击会话输入区或待办页的小鲸鱼，在当前页面上打开阿源浮框，背景页面保持原位且可以操作。浮框内复用原生 DSH 对话、轨迹、模型选择、附件、工具和停止功能；工具栏提供新会话、历史、记忆和建议。拖动标题栏移动，拖动右下角调整大小；本机记住位置、尺寸和视图，重置按钮恢复默认布局。
5. 入口携带少量来源信息，在下一次发消息时提供给阿源；不自动发消息，也不改写草稿。阿源对话中的直接用户消息自动进入可追溯记忆，无须手工填写记忆。
6. 其他设备通过插件管理安装后加入同一中心：**阿源本身共享，手脚不共享**。记忆、偏好、提醒、建议和看板只有中心一份；阿源的会话、模型选择、工具、文件和系统环境留在各自设备。任何一台装了插件的设备都能打开阿源，它就在那台设备上运行并以那台设备的环境执行，记忆读写走中心。

## 0.8.0 跨设备边界

- 设备模式不再把阿源的会话也转发给中心：`open`/`sessions`/`chat`/`activity`/`stop` 在本机执行，只有记忆、提醒、建议、未读信号和看板仍以中心为准。
- 新增 `hub-memory.js`：设备上的阿源通过它读写中心那一份记忆；本机不再保存第二份记忆。
- 浮框标题栏显示运行位置：`中心设备 · 记忆在中心` / `本机运行 · 记忆同步中心` / `独立记忆 · 全权限`。
- 本机 Agent 不可用时仍回落到中心阿源并提示切换设备，不默默另开降级会话。

## 0.7.0 修正

- 从跳转会话改为非模态浮框，通过官方 conversation.content Factory 嵌入原生界面。
- 专用工作区的新建、恢复和插件重载均识别为阿源，首次模型请求之前安装身份、全权限和专用 yuan_context 工具。普通工作区不会得到阿源身份。
- 已归档会话不再被入口恢复或列入阿源历史；历史目录去重。Agent 执行失败或无结果时明确反馈，不再降级成无工具聊天冒充阿源。
- 独立的位置快照不替换背景页面；点击更新位置可继续传入当前选中文字、代码和缩略图。
- DeepSeek 鲸鱼图形轻改为阿源入口，浅蓝底与小星光区分；来源许可见 THIRD-PARTY-NOTICES.txt。

## 0.6.0 改进（数据和记忆部分继续适用）

- 移除嵌套在会话和看板中的自制聊天框，复用宿主原生会话。恢复历史不会覆盖用户选择的模型。
- 待办页默认专注任务；建议、记忆、数据源按需展开。筛选收起，统计合并为一行；作废事项不再计入已完成。
- 页面上下文限制为标题、选中文字、可见代码、最近两条来源文本和最多一张缩略图；10 分钟有效，一次消费，不扫描整页。
- 自动保存直接用户消息，以中文 FTS5 检索相关证据。新消息异步提炼有原文引用的偏好、事实和待核对候选，召回最多 6 条、1600 字符。
- 记忆可查询、查看来源、确认、纠正和忘记；纠正与忘记同步屏蔽旧原文召回，重启和补录不会复活旧记录。忘记是逻辑遗忘，审计日志保留旧版本。

## 0.5.0 修正

- Obsidian 库中的事项自动展示；会话与其他笔记目录的候选需要 Accept。已明确接受的建议及其历史保留，扫描不改原始笔记。
- 停用投影缓存中的 Agent 工作计划作为个人意图证据。通过 DSH `sessionPersistence` 只读 API 增量读取最近主会话，严格检查 `user/message` 与 `source.kind=user`，按 header 排除子 agent，跳过 fork 继承段。
- 会话规则只提取明确的个人承诺/提醒，排除委托 AI、代码、引用、例子和假设。未知归属不冒充「你亲口说的」。这仍是保守规则，不是语义理解已达标。
- 来源标识不依赖笔记行号，重排不会重新推送同一项。日期、优先级、来源和设备保留。
- 修复已接受建议不能完成/恢复的问题；统计以实际待办状态重算。
- 设备中心 API 使用当前 DSH 挂载路径，避免 `/d/<device>/` 页面请求误入根路径 hub relay 导致 401。
- 设备模式共用中心阿源；中心不可用时操作明确报错，不默默另开本地会话。
- 阿源显示执行中文字/工具进度并可取消；执行超时会请求停止；已提交的失败任务不自动重跑。
- 修复热重载复用 Agent 时的提示词/上下文绑定，失败恢复不会偷偷新建空会话；保留原有全权限设置。
- 保存 Markdown 换行，防止中文输入法回车误发送；新建议和已看过的待处理项区分，普通提醒不再误算紧急。
- 已确认记忆按相关词检索后限量注入，保留模型记忆候选的对话来源；待确认记忆不进入提示词。
- 提供 `leo_status` Agent 工具读取待办/建议和更新已确认待办状态。Accept 仍是用户界面操作。

## 设计边界

- `scan.js` 只负责确定性笔记识别；`intake.js` 负责来源证据与会话增量发现；`suggest.js` 保存确认和任务状态。
- `hub-memory.js` 是设备模式的记忆远端适配器；`yuan-agent.js` 管理原生会话及注入；`yuan-context.js` 限制来源片段；`memory-core.js` 管理证据日志、中文索引和记忆生命周期；`yuan.js` 保留旧数据兼容及提醒；`hub.js` / `sync.js` 提供中心同步。
- 记忆目前是可替换的本地基础层，不是「知道你一切」的跨 harness 记忆系统。不会关闭或改写 Codex/CC 的原生记忆。
- 自动记忆目前覆盖阿源会话，不是所有应用的统一记忆。当前采用中文全文检索，没有向量索引，也不承诺自动解决所有语义冲突。新会话的默认模型来自插件配置，之后可在原生界面切换。
- 会话补扫最多最近 40 个主会话，每个新会话从最近 1500 个事件开始，每轮最多读取 300 条；未变日志不重读，每 15 秒限频。不会全盘读取会话全文。未形成明确个人承诺的隐含收尾任务仍可能漏掉。
- 提醒信号在 DSH 页面运行时更新；没有系统级推送或独立常驻提醒调度器。
- 使用新版入口和记忆接口的设备需要升级到 0.6.0；要使用「本机运行 + 中心记忆」的设备需要 0.8.0。已有旧版设备仍可上报笔记，旧 Agent 工作清单会被中心过滤。

## 安装与数据

通过 DSH 插件管理安装本包。已有本地目录安装可替换包文件后在插件管理里禁用/启用，再刷新页面。

默认数据目录：Windows `C:\data\leo-status`，其他平台 `~/.local/share/leo-status`。可通过插件 config `dataDir` 或 `LEO_STATUS_DATA` 覆盖。

`settings.json` 配置 local/hub/device 模式、目录、中心地址及简单密码认证。密码、token、会话和记忆只存数据目录，不进入发行包。

`hub` 中心在本机保存数据，现有 SSH 中转配置继续沿用。本版本不修改设备中心或服务器配置。
