# leo-status 2

入口只有「待办」「时间轴」。这是新的独立笔记库，不扫描或导入 Obsidian，也不改写原文件。

## 使用

- 时间轴「＋记录」打开 Tiptap 编辑器；待办「＋待办」打开含待办块的草稿。
- 输入自动保存。空白页不产生记录；关闭可从时间轴「草稿」恢复。
- Enter 新建待办，Tab / Shift+Tab 调整层级；右侧箭头进入子内容页，面包屑返回。
- 「提交」才更新正式笔记与待办；复选框直接更新同一个 todo，不级联完成子项。
- 时间轴按新加坡时区显示，周一为周首。年/月/周/日下钻，展开 1–4 级，开始/结束时间可切换。
- 图片可粘贴或上传，音视频/PDF 可上传，浏览器支持且授予权限时可录音。
- 标题由独立后台总结会话生成；手动标题优先。时间轴标题菜单可重新生成或恢复上一版模型标题。

## 数据与运行

`<dataDir>/notes-v1/notes.sqlite` 保存唯一正文树、草稿、提交版本、标题与队列；`attachments/` 保存文件。删除进入回收站，不自动删除附件。

默认先合并 60 秒提交，周期自动总结至少间隔 10 分钟。上级等待下级摘要；失败退避重试，SQLite 关闭重开保留队列。后台会话限制为无工具，不向现有阿源聊天发消息。

本机中心保存全部权威数据。device 模式将 API 与附件流转发中心，不落第二份库。当前正在编辑的文字草稿存在浏览器 localStorage，断线重试；未成功上传的附件留在当前窗口，关闭前需重试或明确移除。没有全库离线同步。

## 开发

`npm ci` → `npm run build` → `npm test`。

`src/client.jsx` / `src/style.css` 为源码，`client.js` 为提交到 DSH 的预打包浏览器模块，React 使用宿主版本。Host 入口不依赖扫描器。旧 scan/edit/intake 等文件和旧测试仅为回退参考；不在 2.x 运行入口和发行文件中。`npm test` 运行当前 notes/host/路由生命周期测试，而非已停用的旧扫描器集成测试。

## 本机验收边界

设备中心录音需要中心页面允许嵌入设备请求麦克风，并由用户在浏览器与系统中授权；不同设备的录音权限和键盘行为应分别验证。

## 2.0.0-local.2：交互优化

- 统一内联 SVG，子内容页为原创纸页箭头；树计数紧贴文字，折叠、勾选、进入分开。
- 待办支持总览/按时间。开始取所属笔记最早正式提交时间（后加待办也相同）；完成取真实勾选事件。旧完成时间无法还原时显示未知。
- 完成状态带事件 ID，支持在一次防抖保存期间取消再完成；不新增轮询或模型调用。
- 附件可从相邻文本边界用 Backspace/Delete 移除并撤销；删除引用不会立即删文件。链接使用内嵌编辑弹层。
- 回收站增加单条永久删除与清空，需要界面确认。清理使用明确的ID/版本快照，附件仅在没有其他引用时删除，失败进入持久重试队列。Agent不提供永久清理工具。
- 主导航吸顶并有SVG回到顶部按钮；紧凑行高与更小缩进。桌面弹层尊重宿主标题栏安全区，标题关闭按钮位于右上角。

新接口：GET notes-v1/todos（kind/date/basis=start|completed/q/hideCompleted）；POST notes-v1/trash/purge（items数组，每项id/rev）。state/purge返回cleanupPending数量与cleanupTasks明细。

迁移新增first_submitted及队列字段，不改已有正文。宿主自身的独立总结会话日志仍由DSH管理，不属于插件回收站的删除范围。

## 2.1.0：标签、子笔记和快捷入口

- 笔记级与正文标签支持 `#一级#二级`，搜索可选择范围；兼容旧的斜杠写法。
- 笔记可移动到另一篇笔记下作为独立子笔记，时间轴不重复显示；直接编辑待办会更新正式内容并检查草稿冲突。
- 可选安装 leo-quick-launcher，提供新建待办与录音快捷操作。
